# flickrfree

An invisible Wayland client that holds an **Always-VRR panel at its maximum
refresh** on a static desktop, killing the flicker caused by VRR free-running
down to its low floor (e.g. 48 Hz) whenever nothing animates.

On a monitor set to **VRR = Always**, KWin stops presenting frames the moment
nothing is animating; the panel drops to its minimum refresh, and every input
event rams it back up to max → a visible flicker on each mouse move/keystroke.
`flickrfree` presents a tiny transparent frame every vblank so the compositor
never idles, pinning the panel at max refresh.

It is **fully invisible** (1×1 transparent buffer), **click-through** (empty
input region), and **cannot take keyboard focus** (layer-shell
`keyboard_interactivity = NONE`). While running it shows a **system-tray icon**
(KDE StatusNotifier, lightbulb) with a right-click **Exit** menu.

## Why it doesn't interfere

- **During a fullscreen app** the surface sits on layer-shell **`top`** (below
  fullscreen), so a fullscreen window renders above it. KWin occlusion-culls
  the covered surface → `flickrfree` stops presenting for free, and the app
  gets clean direct scanout (the app holds refresh itself).
- **No EGL/OpenGL.** It uses `wp_single_pixel_buffer_v1` (a 1×1 transparent
  buffer) and `wl_callback.frame` pacing, so it costs almost nothing.

## Build

Requirements: `wayland-client`, `wayland-scanner`, `gcc`, `pkg-config`,
`libsystemd` (for the `sd-bus` StatusNotifier tray), plus `wayland-protocols`
(for the bundled `xdg-shell.xml`). On Arch/CachyOS:

```bash
sudo pacman -S wayland wayland-protocols gcc pkg-config systemd-libs
make               # -> ./flickrfree
```

The protocol XMLs are vendored under `protocols/` and regenerated by `make`.

## Arch package

A `PKGBUILD` is included. Build and install it with:

```bash
makepkg -i        # in this directory

## Run

```bash
./flickrfree             # layer top (pause under fullscreen)  [default]
./flickrfree -l overlay  # sit above fullscreen instead
```

Run it once, then check your monitor OSD stays at max refresh (144 Hz) instead
of falling to its floor. It runs until `SIGINT`/`SIGTERM` or the tray **Exit**
item is chosen.

## System tray + launcher

`flickrfree` registers a KDE StatusNotifier tray item (lightbulb icon, `idea`
from the default icon theme). Right-click it → **Exit** stops the client and
quits. Install it as a normal app:

- **App launcher** (shows in Kickoff like every other app): copy the provided
  `flickrfree.desktop` to `~/.local/share/applications/`.
- **Autostart**: copy it to `~/.config/autostart/`.

Only one instance runs at a time (a lock file in `$XDG_RUNTIME_DIR`); launching
it again while it is already running simply exits.

### Fullscreen-pause verification

Launch a real fullscreen app/game and confirm:
1. it is completely unaffected (clean direct scanout, no interference), and
2. `flickrfree` stops presenting while it is up (occlusion-culled).

If your compositor ever keeps compositing the occluded transparent surface
instead of culling it, switch to the explicit fullscreen-watcher approach.

## Per-output

The layer surface is bound to the first `wl_output` seen at startup. To target
a specific monitor, the output passed to `zwlr_layer_shell_v1.get_layer_surface`
can be selected instead (e.g. via `xdg-output` name matching).

## Design notes

- Focus safety: `keyboard_interactivity = NONE` means the compositor never
  gives it keyboard focus, and the empty input region means it can't be
  clicked — it can't steal focus, ever. `SIGINT`/`SIGTERM` are handled via a
  non-blocking self-pipe so it can always be killed cleanly.
- Libs linked: `wayland-client` (present loop) + `systemd` (sd-bus tray).
